# Android companion

Native Kotlin Android app, minimum Android 10 (API 29), target Android 16 (API 36). It uses Android platform UI, Android Keystore, TLS, MediaProjection, MediaCodec, AudioPlaybackCapture and Accessibility. No third-party runtime libraries beyond Kotlin standard library are used.

## Reproduce the APK

Run `bash build-apk.sh` on this Mac. Defaults use the installed Android Studio JBR, Kotlin compiler and D8 9.3.16, SDK platform `android-36.1`, build tools `36.0.0`. Override `JAVA_HOME`, `KOTLIN_ROOT`, `D8_JAR`, `ANDROID_SDK_ROOT`, `ANDROID_PLATFORM` or `ANDROID_BUILD_TOOLS` to use another compatible installation. D8 must support the compiler's Kotlin metadata version. The direct toolchain avoids downloading Gradle or modifying this Mac's SDK. Run `bash test-wire.sh` for host protocol tests.

Output: `../build/RedmiMirroring-companion.apk`. The development signing key is generated in the Git-ignored build work directory (`.build-work/android-signing/` by default); use `REDMI_BUILD_WORK_DIR` or `REDMI_SIGNING_DIR` to relocate or reuse it, and retain it privately to sign future app updates. The APK is a local development build, not Play Store reviewed software.

## Onboarding

Install only with the phone owner's approval. Open the companion, make it available and create a pairing invitation. Paste the invitation privately into the Mac app, then explicitly approve that Mac on the phone. Enable the disclosed Accessibility control permission in Android settings, approve screen sharing and return to the phone's Home screen. The setup activity is protected by FLAG_SECURE and intentionally appears black in screen captures. Optional audio needs Android's recording permission but uses playback capture, not the microphone.

Pairing invitations expire after five minutes and are never logged or advertised. Service discovery publishes only the device UUID, model and protocol version. Server TLS identity is generated in Android Keystore; its EC key explicitly authorizes raw-digest signing required by Android's TLS provider. Approved client secrets and optional relay settings are encrypted at rest with a Keystore AES-GCM key. Revoke a Mac from the companion or the authenticated Mac unpair command, which acknowledges credential removal before disconnecting. No ADB service is part of this companion.

## Runtime limits

Android 14+ consent is used once to create one virtual display. Rotation/quality changes resize that existing display and replace its encoder surface. Capture remains alive during transient Mac network disconnections. Screen-off stops capture; Android also terminates projection when securely locked on newer releases. A killed app/phone restart needs the owner to reopen it and approve a fresh sharing session. Android recorded HyperOS GarbageClean/OneKeyClean system kills during development; no Java exception was established and the cleaner's manual or automatic trigger is unknown. Accessibility remained enabled but unbound after one kill, requiring owner-assisted rebinding even though video/audio recovered. Use **Open app settings** to review **Battery saver → No restrictions/Unrestricted** and **Background autostart**, and avoid clearing the companion during mirroring. A Recents lock is optional only if this firmware exposes it; Xiaomi's Redmi 14C FAQ says background app lock is unsupported. Standard Android Doze exemption alone does not establish protection from these vendor kills, force-stop, reboot, or memory pressure. No root, Shizuku, lock bypass, private input API or permission auto-grant is used. [Redmi 14C FAQ](https://www.mi.com/pk/support/faq/details/KA-426105/)

The owner re-enabled Accessibility after the recorded kill. Connected/control/live-pointer/projection/audio states were verified active again. Authorized changes to this app's No restrictions battery policy and Background autostart were made through the actual HyperOS UI and verified; global Battery saver was not forced during the later optimization pass. Window/transition/animator durations were reduced to 0.5× through reversible settings. These changes have not been proven to prevent future vendor cleanup.

Touch gestures use Accessibility dispatchGesture; Unicode text and editing keys use Accessibility InputMethod on Android 13+, with a limited focused editable-node text fallback. Unsupported apps/text fields return a visible input error. Touch is refused on securely locked phones, and when capture is known to be an app region rather than the whole display. Live held touches use continuing strokes and Mac updates; a 1,250 ms watchdog releases a stale touch if those updates stop. A real-phone test verified holding beyond four seconds and watchdog release during a 2.5-second Mac app suspension. Audio uses 48 kHz mono PCM16 and depends on the source app's allowed capture policy. Ordinary video congestion preserves queued audio; a brief playback gap can occur while orientation or quality changes rebuild the video encoder. Phone-to-Mac clipboard reads occur only from a visible companion button. Mac files (maximum 32 MiB) are written as pending MediaStore Downloads entries and published only after all bytes arrive. Interrupted transfers delete the pending item.

Remote mode supports either a separately configured private VPN endpoint or an outbound TLS bridge to the included opaque relay. Configure the same private, randomly generated 256-bit room token and relay certificate fingerprint on both devices. The phone's existing TLS and pairing authentication remain inside the relay transport; relay code never decrypts screen/control data. No external account, paid service, Internet endpoint or TURN/ICE service is automatically provisioned. Actual remote deployments require their own test.

Physical-device capabilities must be verified separately from build success. On the test Redmi 14C/Android16, real portrait/landscape streaming, live pointer movement before release, Unicode Mac clipboard paste, and capture/playback audio passed. The current installed APK is byte-identical to the 836,231-byte delivered build, SHA-256 `6e5d6c53b8738078bc186d749c796ee615b59055a1b8d93b7d75d578a93dc834`; its latest continuous-scroll test produced 17 completed movements with zero rejected segments, 12/12 software feedback trials passed, and all six unauthorized TLS cases plus 13 host checks passed. Current Responsive portrait/landscape rotation also passed with control/audio active. A final 30-second live animation/audio run maintained connected/control/projection/audio states, averaged 57.82 decoded fps at 560 × 1280, and played 1,440,960 samples with zero additional audio resets. Later diagnostics recorded additional video drops outside that bounded interval. The owner confirmed responsive control and continuous clean audio. Internet remote use, Android-to-Mac clipboard, long-duration background reliability, and universal low latency remain unverified. See `../TEST-REPORT.md` for quality-specific measurements and each test's scope.

The app's encoder choice and configured width, height, and frame-rate limit are returned to the Mac; settings alone are not measured delivered performance. Surface-input frame rate is explicitly capped. The optional latency hint asks for one frame and retries on a fresh codec without that hint if configuration fails; the actual Redmi reported three frames. Bounded opt-in input/stream timing reports help locate delay without logging text, coordinates, credentials or screen content. After the owner makes the companion available, run `python3 tests/test_unauthorized.py PRIVATE_PHONE_IP` to verify TLS1.2/1.3 unpaired-client and malformed-auth rejection. This negative test intentionally allows an unknown server certificate; production clients always enforce the OOB pin and must never use its test trust configuration.
