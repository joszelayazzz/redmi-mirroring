# Redmi Mirroring wire protocol v1

Transport: TLS 1.2+ TCP, Android server port 39817, Bonjour `_redmimirror._tcp.`. Client MUST pin SHA-256 of DER certificate from out-of-band invitation. No trust-on-first-use. Server identity is Android Keystore EC certificate. Pair invitation `redmimirror://pair?host=<ip>&port=39817&id=<device UUID>&name=<urlencoded>&fp=<64 lowercase hex>&secret=<64 lowercase hex>` expires after 5 minutes. Invitation is a sensitive credential and must not enter logs or public discovery. NSD advertises only id/name/protocol v=1. User transfers invitation from phone to Mac, then explicitly approves new Mac on phone. Persisted 256-bit client secret stored encrypted by Android Keystore AES-GCM and macOS Keychain. One active client; revoke disconnects immediately. Never authorize unauthenticated control.

Framing: 4-byte unsigned big endian size of type+payload, one-byte type, payload. Maximum 16 MiB, zero length invalid. JSON UTF-8 type=1. Codec config type=2 contains Annex-B SPS/PPS. H264 access unit type=3 contains unsigned BE 64-bit presentationTimeUs then Annex-B NAL units. Audio type=4 contains BE64 presentationTimeUs then signed LE PCM16 mono at 48000 Hz. File bytes type=5. Frames can interleave; writes serialized; bounded video queues discard stale frames then request I frame.

Client JSON first: {"type":"auth","version":1,"clientId":"UUID","name":"Mac name","secret":"64 hex","pair":true|false}. Server: {"type":"pending"} until phone approval, then {"type":"ready","deviceId":"UUID","name":"model","width":1080,"height":2400,"fps":60,"audio":false,"control":true,"projection":true}. Paired reconnect pair=false. Reject via {"type":"error","message":"..."}, close. No capabilities/video until authorized. Ready is emitted again on configuration/rotation. Capture can start before or after pairing. {"type":"captureStopped","message":"Approve screen sharing on phone"}. {"type":"ping","sent":<Mac monotonic milliseconds>} echoes as pong with same sent. {"type":"quality","bitrate":8000000,"fps":60,"maxDimension":1920}; encoder may constrain settings, announce actual width,height.

Input {"type":"input","kind":"tap","x":0.5,"y":0.5}, normalized display coordinates. drag: kind=drag, points=[{"x":0.1,"y":0.2},...], durationMs=500. scroll: kind=scroll,x,y,dx,dy (dx/dy normalized finger movement, bounded +/-0.4). pinch: kind=pinch,x,y,scale. text: kind=text,value=Unicode. key: kind=key,key=backspace|enter|tab|left|right|up|down|escape. action: kind=action,action=back|home|recents|volumeUp|volumeDown|lock. Server control refusal/result {"type":"inputResult","ok":false,"message":"..."} where practical. Phone securely locked MUST reject input. Ordinary HID/raw system injection is not claimed; use Accessibility IME API33+, focused editable node fallback.

Live touch extension: ready.livePointer=true when the phone's Accessibility service can accept continued gestures. Client sends {"type":"input","kind":"pointer","phase":"down|move|up|cancel","gestureId":"UUID","seq":0,"x":0.5,"y":0.5}; sequence increases within each gesture. Down begins immediately; moves are coalesced and dispatched as continued Accessibility strokes (normally 16 ms segments), and Up releases at the final point. Client sends Move at most 60 times/second and a stationary Move every 250 ms while held. Server releases the existing stroke after 1.25 seconds without messages, on session disconnection/revocation, lock/screen-off, changed phone geometry, stopped capture or Accessibility interruption. Cancellation ends the existing touch at its last point; it never starts a replacement tap and cannot bypass the lock screen. Only one current and one finishing/waiting pointer are retained; command queues are bounded and preserve Down/Up ordering. Older clients/companions keep the completed-path drag fallback.

Native continuous scrolling consumes this same pointer extension. One scroll sequence begins Down/Move immediately, coalesces updates at most 60 Hz and continues the held touch, then sends Up after a 48 ms end grace or 120 ms idle fallback. The short grace joins finger-end to a following momentum-began event. This adds no privileged input API or separate wire message type.

Optional diagnostic extension: only pointer commands containing a canonical UUID `traceId` enable timing. An optional `source` is echoed only for `mouse` or `scroll`. Server replies with `{"type":"inputTrace","traceId":"UUID","phase":"down|move|up|cancel","seq":0,"stage":"handled|completed|stationary|coalesced|cancelled|ignored|rejected","receivedPhoneMs":0,"mainPhoneMs":0,"dispatchPhoneMs":0,"dispatchReturnPhoneMs":0,"completedPhoneMs":0,"accepted":true,"completed":true}`. Fields are omitted until their event occurred. All phone times use System.nanoTime()/1e6, the same monotonic domain as pong.phoneTime. `handled` marks entry into the main-thread drain; `completed` marks Android's GestureResultCallback for the dispatched segment and does not claim application rendering or touch release for a continuing Down/Move. Coalesced/stationary commands may have no dispatch timestamps. `completedPhoneMs` for other terminal stages is the time processing ended, not a physical gesture completion. At most80 commands/second are traced; diagnostic messages are best-effort and dropped before they fill the normal media queue. No coordinates, text, credentials or screen content enter traces.

A valid traced command enables at most ten seconds of one-second `streamStats` reports, renewed by later traced commands. These contain phoneTime, encoder/configuredFps, encodedFrames in the sample window, encodedPtsAgeMeanMs/encodedPtsAgeMaxMs at the output callback, writerSampledFrames, writerQueueMeanMs/writerQueueMaxMs, writerWriteMeanMs/writerWriteMaxMs and writerQueueDepth. These are software timings; they are not glass-to-glass latency. Ready and streamStats announce requestedLatencyFrames=1, latencyHintApplied and actualLatencyFrames only if the encoder output format supplies it; missing readback does not imply the hint was honored. The optional MediaFormat encoder latency request retries on a fresh codec without that request if configuration fails. The existing virtual display is preserved. Encoder frame-rate quality is additionally enforced with the public surface-input max-fps-to-encoder setting.

Clipboard JSON {"type":"clipboard","text":"..."}, explicit user action, cap 1 MiB; Android->Mac send from visible companion activity only. Do not promise background reads. File JSON fileStart id,name,size <=32MiB then type5 chunks <=256KiB then fileEnd id. Phone writes sanitized basename into app storage or MediaStore Downloads and replies fileResult ok,message. No path traversal/execution. Mac serializes file transfer away from control commands.

Recovery: TLS reconnect with persisted credential using Bonjour device id or saved/manual endpoint. Retry exponential capped 15 s. Existing projection survives transient network loss. Never reuse MediaProjection consent or unlock device. Remote transport supports an independently configured private VPN endpoint or an outbound TLS broker tunnel described in relay/README.md. The original phone TLS certificate pin and authenticated pairing remain inside that tunnel. The broker admission protocol matches opposite roles using a private 256-bit room token; it cannot decrypt the inner media/control stream. Real Internet operation remains unverified, and app-managed ICE/STUN/TURN or direct remote P2P is not implemented.
